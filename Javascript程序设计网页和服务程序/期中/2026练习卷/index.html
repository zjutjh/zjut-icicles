编译型 vs 解释型：JS 的前世今生

1. 通俗理解：同声传译 vs 提前翻译

  • 编译型（如 C/C++）：如同出版外文图书前，翻译人员把整本书一次性翻译成中文并印成书。读者阅读速度极快，但翻译过程（编译）耗时。
  • 解释型（如 JavaScript）：如同外宾讲话时，随行翻译员【听一句、翻译一句、执行一句】。随时可以开始，灵活性极高。

2. 为什么 JavaScript 是解释型的？

  • 1995 年 Netscape 开发 JS 时，初衷是让网页开发轻量化，代码嵌入在 HTML 页面中随加载随解析，无需开发者在本地安装庞大的编译器。
  • 运行环境（宿主）：浏览器（Chrome、Safari 等）或服务端（Node.js）内置了 JS 引擎，负责逐行读取并执行代码。

3. 初学者避坑指南

  • 很多初学者会混淆 Java 与 JavaScript：Java 和 JavaScript 没有任何血缘关系（类似雷锋与雷峰塔）。Java 是强类型编译为字节码的语言，JS 是动态弱类型解释语言。

JavaScript 的数据类型体系全貌

1. JS 中的 8 种数据类型（口诀：4基础 + 2特殊 + 1大数 + 1对象）

  • 记住：NaN 是数值，不是类型！

彻底攻克新手最大梦魇：JS 的 this 究竟是什么？

1. 通俗理解：this 是“谁在叫我”

  • 普通人说话时：“我今天很累。”这里的“我”取决于谁在说话。
  • JS 的普通函数里的 this，完全取决于这个函数是在哪里、被谁调用的（调用位置）。

2. this 的四条绑定规则

1. 默认绑定（独立调用）：foo()

  • 非严格模式下：指向全局对象（浏览器是 window）。
  • 现代标准 / 严格模式下：是 undefined！（本题所考核心）

2. 隐式绑定（作为对象的方法调用）：obj.foo() -> this 指向 obj。

3. 显式绑定（使用 call/apply/bind）：foo.call(target) -> this 强制指向 target。

4. new 绑定（构造函数）：new Foo() -> this 指向新创建的空对象。

3. 箭头函数是个例外！

  • ES6 引入的箭头函数 () => {} 没有自己的 this，它会像普通变量一样沿着作用域链向外找（词法作用域）。

小白也能懂的“闭包”（Closure）背包理论

1. 通俗比喻：背着“登山背包”出生的孩子

  • 普通函数就像是回家脱衣服，函数执行完，里面的临时变量统统被扔进垃圾桶。
  • 当一个函数内部定义了另一个函数时，这个内部函数出生时，顺手打包了一个外部环境背包。
  • 哪怕外层函数早就执行完下班了，内部函数无论被带到天涯海角执行，它依然可以拉开背包，掏出当年外层函数的变量！

2. 极简代码模型


function createCounter() {
  let count = 0; // 外层变量
  return function() {
    count++;     // 内部函数拉开背包访问 count
    return count;
  };
}
const counter = createCounter(); // createCounter 执行完毕！
console.log(counter()); // 输出 1
console.log(counter()); // 输出 2（依然能记住 count！）

单线程的 JS 是如何做到不卡死页面的？

1. 通俗比喻：银行只有一个窗口办事员

  • JS 就像一个只有一个柜员的银行（单线程）。
  • 如果来了一个存钱的，柜员马上办理（同步任务）。
  • 如果来了一个需要去复印材料 10 分钟的（比如网络请求、定时器）：柜员不会傻傻等他 10 分钟，而是对他说：“你先去旁边复印，印好了拿号去排队等待区（任务队列 Task Queue）”。
  • 柜员办完手头的活儿后，抬头看排队等待区，把排好队的人叫过来继续办（事件循环 Event Loop）。

2. 初学者必记结论

  • JS 主线程是单线程的！耗时严重的计算任务不要放在主线程，否则会卡死整个网页。

让函数随时暂停的超能力：生成器（Generator）与 yield

1. 通俗比喻：播放器暂停键

  • 普通函数就像放烟花，一点燃必须一口气放到底（无法中途暂停）。
  • 生成器函数（带 * 号）就像一个带暂停键的视频播放器：
  • 代码里的 yield 就是一个预设的暂停路障。
  • 外界每次按一下遥控器 .next()，视频就播放一小段，并在下一个 yield 前再次自动暂停！

2. 核心考点

  • yield 后面跟的算式会立刻计算并输出给 .value。
  • 下一次调用 .next() 时，函数会从上一次暂停的地方无缝苏醒继续往下走。
