## 第1页：标题页
### 标题
**多核处理器在线程数变化下的性能提升与瓶颈探究**

### 建议内容
- 课程名称
- 小组成员姓名
- 班级 / 学号
- 汇报日期

### 讲解重点
- 简要说明这是一个结合体系结构理论与程序实验的探究项目
- 强调“我们不只是证明多线程更快，而是要分析为什么会快、为什么后来不再明显变快”

---

## 第2页：研究背景与选题意义
### 建议内容
- 为什么主频提升受限
- 为什么多核成为提升性能的重要途径
- 为什么“线程数增加不等于性能线性增长”值得研究

### 可直接放的要点
- 多核处理器是现代计算机的重要性能提升手段
- 程序并不是线程越多越快
- 实际性能会受到调度、缓存、内存带宽等因素影响

### 讲解重点
把问题引到“为什么多核有优势，但又不是无限有效”。

---

## 第3页：研究问题与研究目标
### 建议内容
列出 3~4 个最核心问题：

1. 线程数增加后，运行时间如何变化？
2. 加速比是否接近线性增长？
3. 并行效率为什么下降？
4. Windows 与 Linux 平台上的趋势是否一致？

### 讲解重点
说明本项目既看“性能提升”，也看“性能瓶颈”。

---

## 第4页：理论基础
### 建议内容
- 多核 vs 多线程 vs 流水线
- 加速比公式
- 并行效率公式
- Amdahl 定律

### 可以展示的公式
\[
S_n = \frac{T_1}{T_n}
\]

\[
E_n = \frac{S_n}{n}
\]

### 讲解重点
- 多核是硬件，并行线程是软件执行方式
- 理论上线程增加会提速，但实际存在上限

## 第5页：实验平台与实验程序
### 建议内容
#### Windows 平台
- Intel Core i9-14900HX
- 24 核 / 32 逻辑处理器
- 32 GB 内存

#### Linux 平台
- Debian 12
- Xeon Platinum
- 可见内存约 1.64 GiB

#### 程序
- C++ + OpenMP
- 矩阵乘法
- 对矩阵 B 做转置优化缓存访问

### 讲解重点
说明为什么选择矩阵乘法：计算量大、适合并行、结果稳定。

## 第6页：实验设计
### 建议内容
#### Windows
- 矩阵规模：2400 × 2400
- 线程数：1 / 2 / 4 / 8 / 16 / 24 / 32 / 48 / 64

#### Linux
- 矩阵规模：600 / 1000 / 1400
- 线程数：1 / 2 / 4 / 8

#### 指标
- 运行时间
- 加速比
- 并行效率

### 讲解重点
强调控制变量思想：程序版本不变、规模固定、只改线程数、多次重复取平均。

## 第7页：Windows 结果——运行时间变化
### 建议插图
- `multi_core_experiment/plots/windows_runtime.png`

### 建议文字
- 线程数从 1 增加到 16 时，运行时间显著下降
- 16 线程以后仍有改善，但边际收益减小
- 48 和 64 线程仍略有收益，但已接近平台期

### 讲解重点
这页主要讲“确实变快了”，但要埋下伏笔：后面会看到为什么不是线性变快。

## 第8页：Windows 结果——加速比与并行效率
### 建议插图
- `multi_core_experiment/plots/windows_speedup.png`
- `multi_core_experiment/plots/windows_efficiency.png`

### 建议文字
- 加速比持续增长，但增长速度越来越慢
- 并行效率整体下降
- 24~32 线程区间最值得分析，因为接近平台结构上限

### 讲解重点
把现象和硬件结构联系起来：
- 24 个物理核心
- 32 个逻辑处理器
- 逻辑线程有帮助，但收益不如物理核心阶段明显

### 建议插图
- `multi_core_experiment/plots/linux_runtime.png`
- `multi_core_experiment/plots/linux_speedup.png`

---

## 第10页：综合分析与原因解释
### 建议内容
从三个层次解释结果：

1. **可并行部分带来前期收益**
2. **Amdahl 定律决定收益不可能无限增长**
3. **缓存、内存带宽、线程调度、资源竞争导致后期瓶颈**

### 可直接放的归纳句
- 前期：线程增加，核心利用率提升
- 中期：收益仍有，但边际回报下降
- 后期：更多线程带来的新增收益被开销抵消

### 讲解重点
这一页是答辩的“理论解释页”，很关键。

---

## 第11页：结论
### 建议内容
1. 增加线程数通常能够显著降低运行时间
2. 性能提升不会随线程数线性增长
3. 并行效率会随线程数增加而下降
4. Windows 平台扩展空间更大，Linux 平台更早进入平台期
5. 程序设计方式和平台资源条件同样决定性能表现

### 讲解重点
不要只说“多线程有用”，要说“多线程有用，但有条件、有上限”。

# 一句话答辩总结版

> 本实验通过在 Windows 高性能笔记本和 Linux 云服务器上运行 OpenMP 矩阵乘法程序，验证了多核处理器能够显著提升并行任务性能，但这种提升并不会随着线程数增加而无限线性增长，后期会受到 Amdahl 定律、线程调度、缓存竞争和内存带宽等因素限制，体现出明显的收益递减规律。
