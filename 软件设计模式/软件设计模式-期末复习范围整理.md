## 三、结合老师提醒后的“考试复习范围”判断

### 1. 高概率总范围

考试范围大概率不是只考课堂单独讲过的几个模式，而是按老师说法，**以 23 种设计模式为主线**，再结合：

1. 设计模式基础概念
2. UML 类图
3. 设计原则
4. 各模式的核心意图、结构、适用场景、优缺点
5. 多种模式联合使用

### 2. 你当前最该优先复习的层次

#### 第一层：一定要会

1. 23 种设计模式按三大类的划分
2. 每种模式的：
   - 意图
   - 解决什么问题
   - 核心角色
   - 类图
   - 适用场景
   - 优缺点
   - 与相近模式的区别
3. 常见设计原则与模式之间的关系
4. UML 类图阅读与手绘

#### 第二层：高频重点

1. 策略模式
2. 观察者模式
3. 工厂方法 / 抽象工厂 / 简单工厂的区别与选型
4. 单例模式
5. 适配器模式
6. 装饰器模式
7. 代理模式
8. 组合模式
9. 桥接模式

理由：
这些内容在授课计划中被单独讲过、做过实验、或在往年题中已经出现“联合使用”痕迹。

#### 第三层：联用题重点

根据老师强调“多种模式的联合使用”，需要重点准备下面这类组合：

1. 策略 + 工厂
   - 用工厂创建不同策略对象
2. 观察者 + 代理
   - 数据更新通知 + 访问控制/缓存
3. 组合 + 装饰
   - 树形结构对象 + 动态附加职责
4. 抽象工厂 + 桥接
   - 产品族创建 + 平台/实现分离
5. 外观 + 子系统中的其他模式
   - 对外统一入口，内部再组合多种模式
6. 策略 + 适配器
   - 算法可替换，同时兼容不同接口
7. 观察者 + 中介者
   - 消息分发、模块解耦

## 四、从往年卷面看出的考试形式

已识别出的往年卷明显偏向**综合设计题/类图题/代码分析题**，不是单纯背定义。

### 已出现的题型

1. 阅读代码，说明运行结果，画类图，分析使用了哪些模式，并指出角色对应关系
2. 根据业务需求，要求**必须使用两种指定模式**完成设计，并说明理由
3. 面向一个实际系统场景，要求给出 UML 类图，并说明如何支持扩展
4. 要求给出关键代码

### 这说明复习时必须会

1. 看代码识别模式
2. 从需求反推该用什么模式
3. 画类图
4. 解释“为什么用这个模式，而不是别的模式”
5. 解释“多个模式如何协同工作”

## 五、建议你后续复习时按这个顺序推进

1. 先过一遍 23 种模式总表：分类、定义、角色、场景
2. 再重点攻授课计划里单独讲过和做过实验的模式
3. 专门练“相似模式对比”
   - 工厂方法 vs 抽象工厂
   - 适配器 vs 装饰器 vs 代理
   - 策略 vs 状态
   - 观察者 vs 中介者
   - 组合 vs 装饰
4. 最后专练“多模式联合设计题”
   - 读题
   - 识别需求点
   - 选模式
   - 画类图
   - 说明角色和联用理由
