# 软件设计模式-开卷纸

## 1. 考场总策略

### 1.1 先判断题目在考什么
1. 需求描述选模式
2. 看代码/类图识别模式
3. 补 UML 类图
4. 解释为什么用该模式
5. 多种模式联合使用

### 1.2 五步答题模板
1. 找变化点：以后最可能改的是什么
2. 找稳定抽象：什么接口/抽象不该变
3. 选模式：创建型 / 结构型 / 行为型
4. 画 UML：先抽象，再具体实现，再关联关系
5. 写理由：解耦、扩展、复用、符合开闭原则

### 1.3 标准理由万能句
本题适合使用`XX模式`。因为系统中存在`某种变化点`，若把这些逻辑全部写在同一个类中，会造成`大量条件分支/对象创建耦合/职责过重`。因此可定义统一的`抽象接口/抽象产品/抽象组件`，由不同具体类分别实现。客户端或上下文对象面向抽象编程，在运行时完成`切换/创建/组合/通知/控制访问`。后续若新增功能，只需新增具体实现类，原有核心逻辑无需修改，扩展性较好，符合开闭原则。

## 2. UML 速画规则

### 2.1 基本符号
1. 实线空心三角：继承
2. 虚线空心三角：实现接口
3. 实线箭头：关联/依赖
4. 菱形：聚合/组合
5. 组合比聚合更强：整体没了，部分通常也没了

### 2.2 画图顺序
1. 先画接口/抽象类
2. 再画具体实现类
3. 再画持有它的核心类
4. 最后补箭头和多重性

### 2.3 考场最常见 UML 套路
1. `Context -> Strategy`
2. `Subject -> Observer[*]`
3. `Client -> Factory -> Product`
4. `Decorator -> Component`
5. `Proxy -> RealSubject`
6. `Composite -> Component[*]`
7. `Abstraction -> Implementor`
8. `Facade -> SubsystemA/B/C`

## 3. GoF 23 总表

### 3.1 创建型
1. 单例 Singleton：全局唯一对象
2. 工厂方法 Factory Method：把创建延迟到子类
3. 抽象工厂 Abstract Factory：创建一族相关对象
4. 建造者 Builder：分步骤构建复杂对象
5. 原型 Prototype：通过复制已有对象创建新对象

### 3.2 结构型
1. 适配器 Adapter：接口不兼容时做转换
2. 桥接 Bridge：抽象和实现分离，两维独立变化
3. 组合 Composite：树形结构，整体和部分一致对待
4. 装饰器 Decorator：动态给对象加功能
5. 外观 Facade：给复杂子系统提供统一入口
6. 享元 Flyweight：共享细粒度对象节省内存
7. 代理 Proxy：控制对真实对象的访问

### 3.3 行为型
1. 策略 Strategy：算法/规则可替换
2. 状态 State：状态变，行为变
3. 观察者 Observer：一对多通知
4. 责任链 Chain of Responsibility：请求沿链传递
5. 命令 Command：把请求封装成对象
6. 解释器 Interpreter：定义语法并解释执行
7. 迭代器 Iterator：顺序访问聚合对象
8. 中介者 Mediator：统一协调多个对象交互
9. 备忘录 Memento：保存与恢复状态
10. 模板方法 Template Method：固定骨架，步骤可重写
11. 访问者 Visitor：操作与对象结构分离

### 3.4 补充但不算 GoF 23
1. 简单工厂 Simple Factory
2. 过滤器 / Criteria / Filter Pattern

## 4. 会写代码的高频模式

### 4.1 策略 Strategy
题眼：多种算法/规则可切换

UML 骨架：
1. `Strategy`
2. `ConcreteStrategyA/B implements Strategy`
3. `Context -> Strategy`

最小代码：
```java
interface Strategy { void exec(); }
class A implements Strategy { public void exec(){} }
class B implements Strategy { public void exec(){} }
class Context {
    private Strategy strategy;
    Context(Strategy strategy){ this.strategy = strategy; }
    void run(){ strategy.exec(); }
    void setStrategy(Strategy strategy){ this.strategy = strategy; }
}
```

得分句：
变化点是具体算法/业务规则。将不同算法封装为不同策略类，上下文持有策略接口并在运行时调用具体策略，新增算法时只需新增策略实现类即可。

### 4.2 观察者 Observer
题眼：一个对象变化，通知多个对象

UML 骨架：
1. `Subject`
2. `Observer`
3. `ConcreteObserverA/B implements Observer`
4. `Subject -> Observer[*]`

最小代码：
```java
interface Observer { void update(); }
class A implements Observer { public void update(){} }
class Subject {
    List<Observer> list = new ArrayList<>();
    void add(Observer o){ list.add(o); }
    void notifyAllObs(){
        for (Observer o : list) o.update();
    }
}
```

得分句：
变化点是被通知对象集合。主题对象维护观察者列表，在状态变化后统一通知，各观察者通过统一接口完成不同响应逻辑。

### 4.3 工厂方法 Factory Method
题眼：对象创建过程要解耦，不想客户端直接 `new`

UML 骨架：
1. `Product`
2. `ConcreteProductA/B implements Product`
3. `Factory`
4. `ConcreteFactoryA/B implements Factory`
5. `Factory -> Product`

最小代码：
```java
interface Product {}
class A implements Product {}
class B implements Product {}
interface Factory { Product create(); }
class AFactory implements Factory {
    public Product create(){ return new A(); }
}
```

得分句：
将对象创建职责交给工厂子类完成，客户端只依赖抽象工厂和抽象产品，从而降低与具体产品类的耦合。

### 4.4 抽象工厂 Abstract Factory
题眼：不是创建一个对象，而是创建一整套相关对象

UML 骨架：
1. `AbstractFactory`
2. `createProductA() / createProductB()`
3. `ConcreteFactory1/2 implements AbstractFactory`
4. `AbstractProductA / AbstractProductB`
5. 一套工厂对应一套产品族

得分句：
抽象工厂用于创建同一产品族中的多个相关对象，能够保证产品族之间的一致性。

### 4.5 单例 Singleton
题眼：系统只允许一个实例

UML 骨架：
1. `Singleton`
2. `- instance : Singleton`
3. `- Singleton()`
4. `+ getInstance() : Singleton`

最小代码：
```java
class Singleton {
    private static Singleton instance = new Singleton();
    private Singleton(){}
    public static Singleton getInstance(){ return instance; }
}
```

### 4.6 前 11 节结构型重点 UML

#### 适配器 Adapter
题眼：老接口接不上新系统

UML 速画：
1. `Target`
2. `Adaptee`
3. `Adapter implements Target`
4. `Adapter -> Adaptee`
5. `Client -> Target`

最小理解代码：
```java
interface Target { void request(); }
class Adaptee { void specificRequest(){} }
class Adapter implements Target {
    private Adaptee adaptee = new Adaptee();
    public void request(){ adaptee.specificRequest(); }
}
```

得分句：
将原本不兼容的接口转换为客户端期望的目标接口，使旧类能够在新系统中复用。

#### 装饰器 Decorator
题眼：不改原类，动态加功能

UML 速画：
1. `Component`
2. `ConcreteComponent implements Component`
3. `Decorator implements Component`
4. `Decorator -> Component`
5. `ConcreteDecorator extends Decorator`

最小理解代码：
```java
interface Component { void op(); }
class TextBox implements Component { public void op(){} }
class Decorator implements Component {
    protected Component c;
    Decorator(Component c){ this.c = c; }
    public void op(){ c.op(); }
}
class ScrollDecorator extends Decorator {
    ScrollDecorator(Component c){ super(c); }
    public void op(){ super.op(); addScroll(); }
    void addScroll(){}
}
```

得分句：
装饰器与被装饰对象实现同一接口，通过组合方式在不修改原类的前提下动态扩展对象功能。

#### 代理 Proxy
题眼：不是加新业务功能，而是控制访问

UML 速画：
1. `Subject`
2. `RealSubject implements Subject`
3. `Proxy implements Subject`
4. `Proxy -> RealSubject`
5. `Client -> Subject`

最小理解代码：
```java
interface Subject { void request(); }
class RealSubject implements Subject {
    public void request(){}
}
class Proxy implements Subject {
    private RealSubject real = new RealSubject();
    public void request(){
        check();
        real.request();
    }
    void check(){}
}
```

得分句：
代理对象控制客户端对真实对象的访问，可在调用前后加入权限校验、缓存、日志或延迟加载等逻辑。

#### 组合 Composite
题眼：树形结构，整体和部分统一处理

UML 速画：
1. `Component`
2. `Leaf implements Component`
3. `Composite implements Component`
4. `Composite -> Component[*]`

最小理解代码：
```java
interface Component { void show(); }
class Leaf implements Component {
    public void show(){}
}
class Composite implements Component {
    List<Component> children = new ArrayList<>();
    void add(Component c){ children.add(c); }
    public void show(){
        for (Component c : children) c.show();
    }
}
```

得分句：
将对象组织成树形结构，使客户端对单个对象和组合对象能够统一调用。

#### 桥接 Bridge
题眼：两个维度都在变化，不能一直乘法爆炸

UML 速画：
1. `Implementor`
2. `ConcreteImplementorA/B implements Implementor`
3. `Abstraction -> Implementor`
4. `RefinedAbstraction extends Abstraction`

最小理解代码：
```java
interface Implementor { void draw(); }
class Red implements Implementor { public void draw(){} }
class Blue implements Implementor { public void draw(){} }
abstract class Shape {
    protected Implementor impl;
    Shape(Implementor impl){ this.impl = impl; }
    abstract void show();
}
class Circle extends Shape {
    Circle(Implementor impl){ super(impl); }
    void show(){ impl.draw(); }
}
```

得分句：
将抽象部分与实现部分分离，使两者可以独立扩展，避免多维变化导致类数量爆炸。

## 5. 结构型模式只考判断时怎么抓

### 5.1 一句话口令
1. 适配器：改接口
2. 装饰器：加功能
3. 代理：控访问
4. 组合：树结构
5. 桥接：拆两维
6. 外观：统一入口
7. 享元：共享对象省内存

### 5.2 UML 一眼区分
1. 看到`Adapter -> Adaptee`且`Adapter implements Target`：适配器
2. 看到`Decorator -> Component`且双方同接口：装饰器
3. 看到`Proxy -> RealSubject`且双方同接口：代理
4. 看到`Composite -> Component[*]`：组合
5. 看到`Abstraction -> Implementor`：桥接
6. 看到`Facade -> 多个Subsystem`：外观
7. 看到`FlyweightFactory`管理大量共享对象：享元

### 5.3 补充 UML 模板

#### 外观 Facade
1. `Client -> Facade`
2. `Facade -> SubsystemA`
3. `Facade -> SubsystemB`
4. `Facade -> SubsystemC`

一句话：
对外提供统一入口，隐藏复杂子系统调用过程。

#### 享元 Flyweight
1. `Flyweight`
2. `ConcreteFlyweight implements Flyweight`
3. `FlyweightFactory -> Flyweight`
4. `Client -> FlyweightFactory`

一句话：
共享可复用的细粒度对象，把可共享状态抽出来减少内存开销。

## 6. 易混模式对比

### 6.1 策略 vs 状态
1. 策略：客户端主动选算法
2. 状态：对象因状态变化而自动切换行为

### 6.2 工厂方法 vs 抽象工厂
1. 工厂方法：创建一个产品
2. 抽象工厂：创建一族产品

### 6.3 适配器 vs 装饰器 vs 代理
1. 适配器：改接口
2. 装饰器：加职责
3. 代理：控访问

### 6.4 组合 vs 装饰器
1. 组合：树结构，部分-整体
2. 装饰器：单对象增强，外面包一层

## 7. 多模式联合使用

### 7.1 高频联合
1. 策略 + 简单工厂：工厂创建策略，上下文使用策略
2. 工厂方法 + 策略：不同工厂生产不同策略对象
3. 外观 + 工厂/策略/观察者：Facade 对外统一入口，内部再调用其他模式
4. 组合 + 装饰器：先组织树，再给节点动态加功能
5. 代理 + 观察者：代理控制访问，真实主题变化后再通知观察者

### 7.2 联合题答法
1. 先写主模式解决核心问题
2. 再写辅模式解决创建/增强/通知/访问控制
3. UML 先画主干，再补辅助关系

## 8. 结构型模式考场速答模板

### 适配器
本题适合使用适配器模式。因为现有类接口与客户端所需接口不一致，若直接修改旧类会影响原有系统，因此定义目标接口，由适配器类实现目标接口并组合被适配者对象，在适配器中完成接口转换，从而复用旧类并降低改动范围。

### 装饰器
本题适合使用装饰器模式。因为系统需要在不修改原有类的情况下为对象动态增加功能，因此定义统一组件接口，由具体组件实现基础功能，再由装饰器类持有组件对象并在调用前后附加新职责。后续新增功能时只需新增装饰器类即可。

### 代理
本题适合使用代理模式。因为客户端访问真实对象前后需要加入权限控制、缓存、日志或延迟加载等逻辑，若直接写入真实对象会导致职责混乱，因此定义统一主题接口，由代理对象与真实对象共同实现该接口，客户端面向抽象访问，由代理负责控制真实对象访问过程。

### 组合
本题适合使用组合模式。因为系统对象之间具有明显的树形层次结构，且客户端需要统一处理单个对象与组合对象，因此定义统一组件接口，由叶子节点表示基本对象，由组合节点维护子节点集合并递归调用，从而实现整体与部分的一致对待。

### 桥接
本题适合使用桥接模式。因为系统存在两个独立变化的维度，若采用继承会导致类数量成倍增长，因此将抽象部分与实现部分拆分，通过抽象类持有实现接口引用，使两个维度可以独立扩展，降低类爆炸风险。
